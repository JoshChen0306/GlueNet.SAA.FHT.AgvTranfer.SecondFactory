# 工作計畫：空平板取消連動清源頭

> 詳見同資料夾 `spec.md`（需求/驗收）與 `plan.md`（技術方案）。
> 驗證方式：**手動驗證為主**（DB 造資料 + 開發機/現場實測 + Log），無自動化測試專案、無 TDD 子任務。

## 涉及專案

- `Dispatch\agvFleetManager.sln` → svrPair（raw ADO SQL，產 `svrPair.dll`）
- `WebGui\SCP.sln` → SCP（EF Core）
- DB：`oNeed`、`oRequire` schema migration

## 執行順序

T1（DB schema）→ T2、T3（svrPair：種 + 傳遞 + race）→ T4（SCP model/DbContext）→ T5（SCP DeleteoNeed 連動清源頭）→ 🚦P0→P1 驗證點 → T6（整合手動驗證）

## 單一任務完成 4 道 Gate

每個子任務完成、標記 `[x]` 之前必須全部通過：

| Gate | 檢查項 | 判定 |
|------|--------|------|
| 1. Build | 對應專案建置 | 0 error（warning 允許） |
| 2. Test | TDD: 對應測試 / 一般: 回歸測試 | 全部通過 |
| 3. Acceptance | 逐項核對 spec.md 對應驗收標準 | 全部滿足 |
| 4. Regression | 若屬重構 / 效能優化 | 完整測試套件 0 失敗 |

任一 Gate 失敗 → 標 `[!] 阻塞中` + 停下找使用者，不得跳過。

> 本計畫無測試專案，Gate 2 以「手動回歸（DB 造資料實測 + Log 核對）」替代，並在交付報告註明。

## 跨優先順序驗證點

### 🚦 驗證點 #1：P0 → P1（在進入第一個 P1 任務前執行）

完成的 P0 任務：T1、T2、T3、T4、T5

驗證步驟：
1. 對 svrPair 與 SCP 兩專案各跑一次 Build，0 error。
2. DB 造資料手動回歸：
   - 模擬卡控中的 M→O oNeed（AssignFlag=''）+ 卡控產生的 O→Q（oNeed→oRequire→oMission），確認三表 `ParentTaskDateTime` 一致且等於 T_mo。
   - 在 SCP 取消 O→Q，觀察 M→O oNeed 是否被標 `C` 並於數輪內消失、且不再生新 O→Q。
3. 抽查 spec.md 驗收標準對應 P0 的條目全部滿足。
4. 抽查跨樓層取消（CROSS_FLOOR_DISPATCH / IDLE_RETURN）一筆，確認行為與修復前一致（ParentTaskDateTime 為 oMission 層、清理路徑不變）。

通過 → 進入 T6
失敗 → 停下找使用者討論修復方案，修復後再進入 P1

## 工作項目

- [x] [P0] T1 — DB migration：`oNeed` / `oRequire` 新增 `ParentTaskDateTime varchar(50) NULL`
  ├─ 新建 `Deploy_AddParentTaskDateTime_oNeedoRequire.sql`（仿既有 `Deploy_AddParentTaskDateTime.sql`，含 `IF NOT EXISTS` 防呆）
  ├─ 新檔以 UTF-8 BOM 寫出
  └─ 驗收：兩表皆有該欄位、可重複執行不報錯

- [x] [P0] T2 — svrPair：卡控種下父關聯 + race 防護
  ├─ `cPair.cs:730-733` `CheckAndHandleEmptyPlateRecovery` INSERT oNeed 增 `ParentTaskDateTime`，值 = `dr["TaskDateTime"]`（M→O 的 T_mo）
  ├─ INSERT 前重查父 M→O oNeed 是否仍 `AssignFlag=''`（已被標 C / 不存在 → 不產生 O→Q，記 Log）
  ├─ 改前先驗 `cPair.cs` BOM（No-BOM 含中文先整檔轉 UTF-8 BOM）
  └─ 驗收：O→Q oNeed 的 ParentTaskDateTime = 觸發它的 M→O TaskDateTime；父已取消時不再生

- [x] [P0] T3 — svrPair：父關聯沿 oNeed→oRequire→oMission 傳遞
  ├─ `cPair.cs:463-466` `ProcessoNeedToRequire` INSERT oRequire 增 `ParentTaskDateTime`（取自 `dr["ParentTaskDateTime"]`，DBNull 防呆）
  ├─ `cPair.cs:593-596` `InsertoMission` INSERT oMission 增 `ParentTaskDateTime`（取自 oRequire 列，DBNull 防呆）
  └─ 驗收：三表 ParentTaskDateTime 一致；一般任務（無父關聯）寫入為 NULL、轉表不丟例外

- [x] [P0] T4 — SCP：EF model 與 DbContext 加欄位
  ├─ `WebGui\SCP\Models\oNeed.cs`、`oRequire.cs` 各加 `public string? ParentTaskDateTime { get; set; }`
  ├─ SCP 的 `agvDB_*Context.cs` `OnModelCreating` 對 oNeed/oRequire 各加 `.Property(e => e.ParentTaskDateTime).HasMaxLength(50)`（仿 oMission 既有設定）
  ├─ 改前先驗各檔 BOM
  └─ 驗收：SCP 專案 Build 0 error

- [x] [P0] T5 — SCP：`DeleteoNeed` 連動清源頭
  ├─ `DispatchController.cs:274-328`：取 `ParentTaskDateTime` 改為「先查 oMission，找不到退查 oRequire」
  ├─ cancelList 沿用既有父子收集邏輯（含跨樓層）
  ├─ 迴圈內**新增**：對每筆 `tdt` 標 `oNeed.AssignFlag='C'`（`ExecuteUpdate`），保留既有 oMission/oRequire `OkFlag='C'`
  ├─ 包在既有 transaction；catch 至少記 Warning（不可空 catch）
  └─ 驗收：取消 O→Q 後 M→O oNeed 被標 C；跨樓層/一般任務取消行為不變

- [ ] [P1] T6 — 整合手動驗證（端到端）
  ├─ 場景 A：卡控中 M→O + 執行中 O→Q，SCP 取消 O→Q → 驗 M→O oNeed 清除、AGV 收到 Cancel、不再重生
  ├─ 場景 B：O→Q 僅在 oNeed/oRequire（未派車）時取消 → 驗 parent 經 oRequire fallback 仍被清
  ├─ 場景 C（回歸）：一般搬運任務、跨樓層任務取消 → 行為與修復前一致
  ├─ 場景 D（race）：父已標 C 後跑數輪迴圈 → 無新 PLATE_RECOVERY oNeed
  └─ 驗收：spec.md 全部驗收標準逐項核對通過，產出手動驗證紀錄
