# 工作計畫 — 歷史任務統計頁後端真分頁

- 主題：歷史任務統計頁(Tasks)明細改後端真分頁，開放超過 30 天查詢
- 分析力度：標準模式
- 相關文件：`spec.md`、`plan.md`
- TDD 判斷：**全部非 TDD**（改動綁定 EF DBContext 與前端 DataTables，屬整合／UI／設定層；SCP 無測試專案）

## Commit 策略

- 每個子任務完成後獨立 commit。
- 格式：`fix(scp): ...` 或 `feat(scp): ...`，訊息以繁體中文描述。
- 純結構性重構與行為變更拆成不同 commit。

## 執行順序

P1 三項為治本核心（後端 API → 前端 serverSide → 匯出全量），需依序完成並整合；
P2 為放寬限制與整體回歸驗證，於 P1 全部完成後進行。

## 單一任務完成 4 道 Gate

每個子任務完成、標記 `[x]` 之前必須全部通過：

| Gate | 檢查項 | 判定 |
|------|--------|------|
| 1. Build | 對應專案建置 | 0 error（warning 允許） |
| 2. Test | TDD: 對應測試 / 一般: 回歸測試 | 全部通過 |
| 3. Acceptance | 逐項核對 spec.md 對應驗收標準 | 全部滿足 |
| 4. Regression | 若屬重構 / 效能優化 | 完整測試套件 0 失敗 |

任一 Gate 失敗 → 標 `[!] 阻塞中` + 停下找使用者，不得跳過。

> 環境限制：SCP（WebGui）無測試專案，Gate 2 / Gate 4 以**手動回歸驗證**替代（查詢、翻頁、排序、搜尋、匯出、統計/圖表行為比對），並於報告註明「agent 缺席／環境限制，已 fallback 手動驗證」。

## 跨優先順序驗證點

### 🚦 驗證點 #1：P1 → P2（在進入第一個 P2 任務前執行）

完成的 P1 任務：任務 1、任務 2、任務 3

驗證步驟：
1. 手動回歸：明細 tab 在 serverSide 下翻頁、排序、搜尋皆正確，頁數與總筆數相符
2. 手動回歸：CSV/Excel 匯出可匯出整個查詢範圍（非只當前頁）
3. 抽查 spec.md 驗收標準對應項目（後端分頁、排序搜尋、匯出）全部滿足
4. 確認既有防呆（壞列略過、車輛未登錄退回顯示）在分頁後仍生效

通過 → 進入 P2 任務
失敗 → 停下找使用者討論修復方案，修復後再進入 P2
