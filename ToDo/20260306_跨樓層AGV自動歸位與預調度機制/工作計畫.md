# 跨樓層 AGV 自動歸位與預調度機制

## 建立日期
2026-03-06

## 需求說明

### 問題背景
二廠共有三輛 AGV，其中一輛為跨樓層車輛。目前存在兩個問題：
1. 跨樓層車輛閒置時停留在非 4F 樓層，無法及時回歸母樓層
2. 使用者建立跨樓層任務時，車輛不在起點樓層，需先調度車輛才能接收任務

### 需求細節
- **閒置歸位：** 當跨樓層車輛狀態為 IDLE 且不在 4F，等待可設定時間（預設 5 分鐘）後自動歸位至 4F
- **任務預調度：** 跨樓層任務建立時，若車輛不在起點樓層，自動產生調度任務先送車至該樓層
- **歸位過程中收到新任務：** 已送出歸位任務則完成歸位後再接新任務；尚未送出（計時中）則取消計時，按佇列邏輯派發

### 競態問題處理
場景：車在 4F，任務1 為 2F->4F（需預調度），任務2 為 4F->3F（同樓層可直接執行）。
解法：跨樓層車輛的所有任務由 CrossFloorManager 統一管控派發，一次只派一筆，避免 RCS 自動接走同樓層任務導致預調度失敗。

## 選定方案

**方案：獨立模組 CrossFloorManager**

在 `ACC/HikAGVWebAPI/HikAGVWebAPI/App_Start/` 新增 `CrossFloorManager.cs`，負責：
- 攔截所有跨樓層車輛的 oMission，統一排序與派發
- 閒置歸位監控（IDLE 超時回 4F）
- 預調度任務產生與管理
- 一次只派一筆任務，等 Callback 完成再派下一筆

### 任務派發優先邏輯
```
車輛 IDLE 時，從待派發佇列中：
1. 同樓層任務優先（車在哪就先做哪）
2. 同優先順序時，依任務建立時間排序（先進先出）
3. 佇列中無同樓層任務 -> 送預調度到最早任務的起點樓層
4. 佇列完全為空 -> 啟動閒置計時，超時歸位 4F
```

### 設定檔新增項目（FHtSetting.config / HikAGV.config）
- `CrossFloorShuttleId`：跨樓層車輛編號
- `IdleReturnTimeout`：閒置歸位超時秒數（預設 300）
- `IdleReturnFloor`：歸位目的地樓層（固定 4F / MapCode FF）

### 任務名稱定義
- 歸位任務：`IDLE_RETURN`
- 預調度任務：`CROSS_FLOOR_DISPATCH`

### Dispatch.cs 修改
- `AGVSchedulingTask()` 中，跨樓層車輛的任務不直接派發，交由 CrossFloorManager 處理
- 其餘非跨樓層車輛的任務維持原有邏輯不變
