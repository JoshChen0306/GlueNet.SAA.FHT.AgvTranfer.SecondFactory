# 技術方案書 — 派工任務畫面平板縮放變形修復

## 選定方案概述

**方案 A：地圖整體 `transform: scale()` 動態縮放 + 按鈕表單獨立 RWD（雙軌分治）**

把「地圖」與「按鈕表單」兩種佈局分開治理：
- 地圖：對固定 1400×800 的 `#Map`（或其外層 wrapper）套 `transform: scale(k)`，`k` 依父容器實際寬度動態計算，整張圖層等比例縮放、內部相對關係不變 → 不變形。
- 按鈕表單：走 Bootstrap 平板斷點 RWD 重排，**不**跟地圖一起 scale。

## 架構設計

### 元件關係與資料流向

```
容器寬度 (resize) ──► JS 計算 k = 容器可用寬 / 1400
                         │
                         ▼
   #Map wrapper { transform: scale(k); transform-origin: top left;
                  height: 800 * k }   ← 補正佔位，避免留白/重疊
                         │
        ┌────────────────┴────────────────┐
        ▼                                  ▼
  底圖(background)                庫位 .trac / AGV(絕對定位)
  ──── 全部相對 #Map 等比例縮放，位置關係不變 ────

按鈕/表單區（獨立於地圖 scale 之外）
   Bootstrap 平板斷點 media query → 重排 col、加大按鈕觸控尺寸
```

### 關鍵改動點（施工前逐項與使用者確認細節）

| 檔案 | 預計改動 | 待討論細節 |
|------|---------|-----------|
| `wwwroot/js/Map.js`（或新增小段 JS） | 計算並套用 scale、監聽 resize、補正 wrapper 高度 | k 的計算基準（父容器 vs 視窗）、是否 debounce、初次載入時機 |
| `Views/Shared/_MapPartial.cshtml` | `#Map` 外層加 wrapper、`transform-origin` 設定 | wrapper 結構、是否影響現有 `#Map` 選擇器 |
| `Views/Dispatch/Index.cshtml` | 按鈕/表單區平板斷點 RWD（col 重排、按鈕尺寸） | 斷點值、直向堆疊 vs 調比例、按鈕最小觸控尺寸 |
| `Views/Shared/_Layout.cshtml` | viewport 驗證（現況已正確，多半不需改） | 是否需針對地圖頁處理 pinch zoom fallback |

## 方案分析（六面向）

1. **方案概述**：地圖當成單一圖層等比例 scale、按鈕表單獨立 RWD，雙軌分治。
2. **架構設計**：見上。利用「庫位/AGV 皆相對 `#Map` 絕對定位」的既有特性，scale 外層即可整體縮放，改動內聚。
3. **優點**：
   - 直接消除變形觸發條件（不再需要手動縮放）。
   - 地圖 scale 不破壞內部相對定位與點擊熱區。
   - 動態計算涵蓋多種平板解析度，不綁死尺寸。
   - 純前端、改動集中、可局部驗證、桌機不受影響。
4. **風險與缺點**：
   - `transform: scale` 後外層佔位需手動補正（高度），否則產生留白/重疊。
   - 高倍縮小時底圖文字可能較小，需實機確認可讀性。
   - 按鈕 RWD 斷點需與地圖 scale 後的版面協調，避免互相牽動。
5. **技術債評估**：
   - 地圖仍是固定 1400×800 + JS scale，屬「等比例貼合」而非原生自適應。若日後要完全響應式，仍需改 SVG viewBox（見下）。維護成本低、可讀性佳。
6. **建議適用情境**：既有固定 px 畫布要快速貼合多種平板、又不想重寫繪製架構 —— 即本需求。

## 被捨棄的方案

- **方案 B：地圖改 SVG `viewBox` 原生自適應**
  - 捨棄原因（本次）：需重寫 `_MapPartial` 與 `Map.js` 繪製與座標系，工程量中大、風險高。列為後續治本選項。
- **方案 C：只放大字級 / 只調 Bootstrap 斷點，不處理地圖固定尺寸**
  - 捨棄原因：治不到地圖 1400px 固定的根因，變形依舊。
- **方案 D：維持現狀，靠使用者手動瀏覽器縮放**
  - 捨棄原因：這正是變形來源。
