# 工作計畫 — 派工任務畫面平板縮放變形修復

- 主題：派工任務畫面在平板上因手動瀏覽器縮放造成地圖庫位與按鈕變形，改為自動貼合免手動縮放
- 分析力度：標準模式
- 相關文件：`spec.md`、`plan.md`
- TDD 判斷：**全部非 TDD**（純前端 CSS/JS 佈局與樣式調整；SCP 無測試專案）

## ⚠️ 全域前置規則：施工前討論

> 使用者明確要求：**本計畫僅先建立，每個施工子任務開工前都必須先與使用者討論實作細節並取得確認，才可動手改。**
> 每個子任務下方均設「🚧 施工前討論關卡」，未完成討論不得進入實作。

## Commit 策略

- 每個子任務完成後獨立 commit。
- 格式：`fix(scp): ...`，訊息以繁體中文描述。
- 樣式/佈局調整與行為調整（JS）可分開 commit。

## 執行順序

先做地圖等比例 scale（核心，P1）→ 按鈕/表單 RWD（P1）→ viewport 與縮放行為驗證（P2）。
每項開工前先討論實作細節。

## 單一任務完成 4 道 Gate

每個子任務完成、標記 `[x]` 之前必須全部通過：

| Gate | 檢查項 | 判定 |
|------|--------|------|
| 1. Build | 對應專案建置 | 0 error（warning 允許） |
| 2. Test | TDD: 對應測試 / 一般: 回歸測試 | 全部通過 |
| 3. Acceptance | 逐項核對 spec.md 對應驗收標準 | 全部滿足 |
| 4. Regression | 若屬重構 / 效能優化 | 完整測試套件 0 失敗 |

任一 Gate 失敗 → 標 `[!] 阻塞中` + 停下找使用者，不得跳過。

> 環境限制：SCP（WebGui）無測試專案，Gate 2/4 以**手動回歸驗證**替代 —— 實機平板（多種解析度）+ 桌機瀏覽器比對，驗證地圖完整顯示、庫位點擊、按鈕操作、桌機不退化。報告註明「agent 缺席／環境限制，已 fallback 手動驗證」。

## 跨優先順序驗證點

### 🚦 驗證點 #1：P1 → P2（在進入第一個 P2 任務前執行）

完成的 P1 任務：任務 1、任務 2

驗證步驟：
1. 手動回歸：平板 100% 縮放下地圖完整顯示、等比例不變形、resize 正常
2. 手動回歸：庫位點擊熱區、tooltip、物料 Modal 正常
3. 手動回歸：表單與下方按鈕在平板寬度下排列整齊、可正常操作送出
4. 桌機比對：原正常解析度顯示不退化
5. 抽查 spec.md「地圖 scale」「按鈕/表單 RWD」驗收標準全部滿足

通過 → 進入 P2 任務
失敗 → 停下找使用者討論修復方案，修復後再進入 P2

## 工作項目

- [ ] [P1] 地圖 `#Map` 動態等比例 scale
  └─ 非 TDD：純前端 JS/CSS 佈局
  - 對 `#Map`（或新增 wrapper）套 `transform: scale(k)` + `transform-origin: top left`
  - `k = 父容器可用寬 / 1400`，JS 動態計算、監聽 `resize` 重算
  - wrapper 高度補正為 `800 * k`，避免留白/重疊
  - 確認縮放後庫位點擊熱區、tooltip、物料 Modal 定位正常
  - 🚧 施工前討論關卡：k 計算基準（父容器 vs 視窗）、是否 debounce resize、初次載入套用時機、wrapper 結構是否影響現有 `#Map` 選擇器與 AGV 定位

- [ ] [P1] 按鈕/表單區平板斷點 RWD
  └─ 非 TDD：純前端 CSS 佈局
  - 平板斷點下重排 `col-5/col-7`（直向堆疊或調比例），下方按鈕加大觸控尺寸
  - 此區不跟地圖一起 scale，獨立自適應
  - 確認各下拉/輸入/送出按鈕在平板寬度可正常操作
  - 🚧 施工前討論關卡：斷點值（如 ≤992px / ≤768px）、直向堆疊 vs 調比例、按鈕最小觸控尺寸、是否影響桌機版面

- [ ] [P2] viewport 與縮放行為驗證/微調
  └─ 非 TDD：設定驗證
  - 確認 `_Layout.cshtml` viewport 維持 `width=device-width, initial-scale=1.0`（現況已正確）
  - 實機確認 P1 完成後預設 100% 即可完整操作、無需手動縮放
  - 視需求評估是否針對地圖頁處理 pinch zoom fallback
  - 🚧 施工前討論關卡：是否需要保留/禁用使用者手動縮放、是否要加「重置縮放」提示
