# 需求規格書 — 派工任務畫面平板縮放變形修復

## 主題與背景

派工任務畫面（SCP / `Dispatch/Index.cshtml`）在現場平板上，因平板解析度不足以容納畫面，操作員以**瀏覽器手動縮放（Ctrl +/- 或 pinch）** 遷就顯示，導致**地圖庫位與下方按鈕變形／錯位**。

### 根因（已讀程式碼確認，高信心）

畫面由兩種性質完全不同的佈局擠在一起：

| 區塊 | 佈局方式 | 縮放時行為 |
|------|---------|-----------|
| 地圖／庫位（`_MapPartial.cshtml` 的 `#Map`） | **寫死 `width:1400px; height:800px` 固定畫布**；庫位 `.trac` 為 `position:absolute` + `left/bottom` 固定 px；底圖 `background-size:1400px 800px`；AGV 亦絕對定位 | 完全不自適應，是一塊死尺寸圖層 |
| 表單／下方按鈕（`Dispatch/Index.cshtml`） | Bootstrap grid（`col-5/col-7`、`col-2/col-10`、`w-75`、flex） | 會 reflow，隨寬度換行、擠壓 |

瀏覽器縮放會改變等效 viewport 寬度 → 觸發 Bootstrap 響應式斷點使按鈕區 reflow，但固定 1400px 的地圖不跟著變 → 兩邊步調脫節 → 變形。

治本目標：**讓畫面在瀏覽器 100% 縮放下即自動排好，操作員不需再手動縮放**，變形觸發條件即消失。

## 需求範圍

### 包含
1. 地圖 `#Map` 依**容器實際寬度動態**等比例縮放（`transform: scale(k)`），k 由 JS 動態計算、`resize` 時重算。
2. 表單與下方按鈕在平板斷點下 RWD 重排、加大觸控尺寸，**不跟地圖一起 scale**。
3. viewport 與縮放行為驗證／微調（meta 現況已正確，見限制條件）。

### 不包含
- 不改地圖後端資料（`GetMap` / `_MapPartial` 的庫位座標資料）與派工商業邏輯。
- 不改地圖繪製為 SVG viewBox 架構（治本但工程大，列為後續選項，見 plan.md）。
- 不處理其他頁面（僅派工任務畫面）。

## 限制條件

- **目標解析度：動態**。不鎖單一尺寸，scale 依 `#Map` 父容器實際可用寬度計算，涵蓋多種平板。
- viewport meta **現況已為** `width=device-width, initial-scale=1.0`（`_Layout.cshtml:6`），基礎設定正確；本次以「驗證＋視需求微調」為主，非重寫。
- 全部為**純前端 CSS/JS 調整**（`_MapPartial.cshtml`、`Dispatch/Index.cshtml`、`Map.js` / 相關 css），不動後端、不動 EF、不改資料 → **非 TDD**（純 UI 佈局）。
- SCP（WebGui）**無測試專案**，Gate 2/4 以**手動回歸驗證**（實機平板 + 桌機瀏覽器）替代，報告註明環境限制。
- **每個施工項目開工前，需先與使用者討論實作細節並取得確認，才動手改。**（使用者明確要求）

### 資料流
本需求為純前端顯示層調整，不涉及 PLC／DB／外部 API 讀寫，無資料流表。

## 驗收標準

### 地圖等比例 scale
- [ ] 平板瀏覽器 100% 縮放下，地圖（含所有庫位、AGV、底圖）完整顯示於可視範圍，無需手動縮放
- [ ] 地圖等比例縮放，庫位方塊／AGV 圖示／底圖相對位置正確，不錯位、不變形
- [ ] 視窗／容器寬度變化（resize）時地圖重新計算縮放並維持完整顯示
- [ ] 縮放後庫位點擊熱區正確（點得到正確站點，tooltip / 物料 Modal 正常）

### 按鈕/表單 RWD
- [ ] 平板寬度下，派工表單與下方按鈕排列整齊，不擠壓、不換行變形
- [ ] 下方按鈕觸控尺寸適合手指操作
- [ ] 表單各下拉／輸入欄位在平板寬度下可正常操作與送出

### viewport 與縮放行為
- [ ] 確認 viewport meta 維持 `width=device-width, initial-scale=1.0`
- [ ] 預設載入即 100% 對齊裝置寬度，操作員無需手動縮放即可完整操作

### 整體
- [ ] 桌機（原正常解析度）顯示不退化，維持原樣
