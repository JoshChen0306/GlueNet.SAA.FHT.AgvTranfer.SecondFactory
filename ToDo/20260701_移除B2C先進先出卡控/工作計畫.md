## 需求說明

### 現況（已逐行讀程式碼確認）
做 B→C 時，B 區物料下拉以「料號」分組，每個料號只顯示 PutTime 最早的一盤，
其餘同料號站點被隱藏、選不到 → 即客戶說的「只能先選先到的物料」。

### 待確認的關鍵決策點（明天問客戶）
> 客戶要的是「完全不要任何先進先出限制」，還是「要能自由選批號，
> 只是不希望被同料號的其他盤擋住」？

- **若答案是前者** → 直接移除 `case "C"` 的 FIFO 過濾，B 區同料號所有 HaveFlag=3 站點全顯示。
- **若答案是後者** → 應把分組 key 從「料號」改成「批號」（或料號+批號），
  保留 FIFO 精神又不誤擋不同批號，風險更低。

## 關鍵程式位置（實證）

| 項目 | 位置 |
|------|------|
| FIFO 卡控主體 | `WebGui/SCP/wwwroot/js/Dispatch.js` → `filterBeginStationOptions()` 的 `case "C"`（約 1595-1640 行） |
| 分組 key | WorkOrder 以 `^` 分割第 4 段（index[3]）= 料號；批號 lot 為第 3 段（index[2]，僅顯示用） |
| 顯示格式 | `站號-料號-批號`（case "C" 的 `.each()` 內） |
| PutTime 寫入 | `WebGui/SCP/Controllers/DispatchController.cs` → `RegisterLot`(:557) 以 `yyyyMMddHHmmssffffff` 寫入；`ClearLot`(:607) 清空 |
| 為何在前端 | 此廠 `Recipe.ini` 為 `PanelDoB2C=T`，B→C 由平板/Web 人工操作；svrPair 自動配對 `GenerateoNeedDataByMCSAsBtoC()`（`cPair.cs:118-120`，權重路徑）不執行 |

## 影響評估摘要
- **正面**：同料號 B 區所有 HaveFlag=3 站點都能選。
- **風險1**：失去 FIFO 防呆 → 若有料齡/時效管控，舊料可能積壓過期，全靠人員自律。
- **風險2**：下拉變長，同料號多盤全列出，選錯盤機率上升。
- **風險3**：後端 `InsertoNeed` 本就未驗證 FIFO，移除後無任何一層擋。
- **影響範圍**：FIFO 只在 `case "C"`（1F B→C）。同函式還有 `H/M/T/MT` 等 2F case，
  改動時**不可動到共用 `workoderMap` 或其他 case**，避免誤傷 2F。
