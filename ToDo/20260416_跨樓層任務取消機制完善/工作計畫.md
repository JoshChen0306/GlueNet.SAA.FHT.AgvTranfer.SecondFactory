## 需求說明

### 問題背景

跨樓層系統任務（IDLE_RETURN / CROSS_FLOOR_DISPATCH）存在以下已知問題：
1. SCP 看不到系統任務（直接寫 oMission 跳過 oRequire）
2. 取消預調度後系統 LOOP 重建（MCS 任務仍在，下一秒再生預調度）
3. DeleteMission 不通知 CrossFloorManager 重置旗標
4. UpdateCancel 缺少 Update_oRequire
5. 網路斷線 / RCS 異常時任務卡住無法清理
6. 同起訖點多筆任務取消會互相誤殺

### 解決方案摘要

| 問題 | 解法 |
|------|------|
| SCP 不可見 | 方案 C：系統任務同時寫 oMission + oRequire |
| LOOP 重建 | 連動取消：取消任一端時自動取消關聯任務，強制先 MCS 後預調度 |
| DeleteMission 缺口 | 補 CrossFloorManager 通知 |
| UpdateCancel 缺口 | 補 Update_oRequire |
| 網路斷線卡住 | 跨樓層走 fire-and-forget（不等 RCS 回應直接清 DB）+ ubCancelLog |
| 同起訖點誤殺 | SCP DeleteoNeed 改用 TaskDateTime 匹配 + ParentTaskDateTime 關聯 |

## DB Schema 變更

### 既有資料表新增欄位

| 資料表 | 新增欄位 | 型別 | 說明 |
|--------|---------|------|------|
| oMission | ParentTaskDateTime | varchar(50), NULL | 觸發此預調度的 MCS 任務 TaskDateTime |
| ubMission | ParentTaskDateTime | varchar(50), NULL | 歸檔保留（Insert_ubMission 用 select *，兩表欄位須同步） |

### 新增資料表

**ubCancelLog** — 記錄所有取消操作

| 欄位 | 型別 | 說明 |
|------|------|------|
| CancelTime | datetime | 取消時間 |
| Operator | varchar(50) | 操作人員（SCP 登入帳號） |
| TaskDateTime | varchar(50) | 被取消任務的 TaskDateTime |
| ParentTaskDateTime | varchar(50), NULL | 關聯的 MCS TaskDateTime |
| TaskSource | varchar(50) | MCS / CROSS_FLOOR_DISPATCH / IDLE_RETURN |
| BeginStation | varchar(10) | 起點 |
| EndStation | varchar(10) | 終點 |
| TaskCode | varchar(50) | RCS 端任務碼 |
| RcsCancelResult | varchar(200) | RCS Cancel API 回應 |
| LinkedTaskDateTimes | varchar(200), NULL | 連動取消的其他任務 TaskDateTime |
