# 修正 IDLE 偵測誤觸歸位

## 根因分析

`CrossFloorManager.Tick()` 判斷車輛是否閒置時，**只依賴 RCS 即時回報的 `oShuttle.Status`**。
但 RCS 在跨樓層任務途中可能短暫回報非執行狀態（如等電梯、遇障暫停），
導致 `UpdateAGVStatus()` 將 Status 覆寫為 "I"，Tick() 誤認車輛閒置並啟動 IDLE 歸位計時。

客戶案例（2026/04/10）：
- 23:46:59 F24Test（MCS, H1→K1, 2F→4F）派發給車輛 20106，RCS 回報 start callback
- 23:47:24 Tick() 偵測到 Status="I"，啟動 IDLE 計時（此時 F24Test 仍在執行）
- 23:48:43 閒置超時 79s，寫入 IDLE_RETURN 至 oMission
- 結果：F24Test（OkFlag="R"）擋住 IDLE_RETURN 派發，IDLE_RETURN 擋住後續任務，**系統死鎖 3 天**

無法用 `oMission.ShuttleId` 判斷任務屬於哪台車，因為 ShuttleId 要等 start callback 才寫入，
在 DispatchMission 到 start callback 之間是 0。
改用現有 `IsMissionForCrossFloorShuttle()` 依起終站判斷任務是否屬於跨樓層管轄。

## 修正方案

在 `Tick()` 的 `shuttle.Status == "I"` 判斷之前，查詢 oMission 是否有 OkFlag="R" 且屬於跨樓層的任務。
若有，重置 IDLE 計時並跳過，避免在任務執行途中誤觸歸位。
