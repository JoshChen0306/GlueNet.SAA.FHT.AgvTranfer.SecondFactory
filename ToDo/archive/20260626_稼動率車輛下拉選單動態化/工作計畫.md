# 稼動率查詢頁 車輛下拉選單動態化 — 工作計畫

> 主題：把稼動率（歷史任務統計）查詢頁寫死的車輛下拉選單改為從 `oShuttle` 動態載入
> 背景：前一份計畫 `20260626_稼動率UI查詢500錯誤修復` 的 T4 調查結論 ——
>       `Views/Tasks/Index.cshtml:18-22` 只硬編 `AGV-1`/`AGV-2`，二廠 3F/4F 新車選不到，
>       導致客戶反映「其他車查不到」。T1~T3 已止血（不再 500），本計畫治本。
> 分析力度：精簡模式（單一子任務、純 UI 資料繫結，非 TDD）
> 採用方案：Server-side Razor（Index Action 填 ViewBag、Razor 迴圈產生 option）

## 單一任務完成 4 道 Gate

每個子任務完成、標記 `[x]` 之前必須全部通過：

| Gate | 檢查項 | 判定 |
|------|--------|------|
| 1. Build | 對應專案建置 | 0 error（warning 允許） |
| 2. Test | TDD: 對應測試 / 一般: 回歸測試 | 全部通過 |
| 3. Acceptance | 逐項核對 spec.md 對應驗收標準 | 全部滿足 |
| 4. Regression | 若屬重構 / 效能優化 | 完整測試套件 0 失敗 |

任一 Gate 失敗 → 標 `[!] 阻塞中` + 停下找使用者，不得跳過。

> 註：本計畫採精簡模式無 spec.md，Gate 3 驗收標準直接列於下方「驗收標準」段。
