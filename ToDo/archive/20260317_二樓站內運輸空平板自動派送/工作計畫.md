# 二樓站內運輸空平板自動派送

## 建立日期
2026-03-17

## 需求說明

### 問題背景
目前 2F 站內運輸的空平板派送流程為**手動操作**：操作人員需先選擇空庫位，再點選 Release 按鈕才會派送空平板。客戶希望將此流程**自動化**。

### 核心需求
當物料要派送至上料區（O/P）時，下料區（Q）必須有空平板才能收料。系統需自動完成：
1. **檢查下料區空平板**：確認對應下料區是否有空平板
2. **自動回收空平板**：若下料區無空平板，先將上料區的空平板回收至下料區
3. **派送實際物料**：空平板到位後，再將物料搬運到上料區

### 物料派送來源
| 來源區域 | 說明 | 目的地 |
|----------|------|--------|
| M 區（雷雕區） | M → O/P/T | 上料區 |
| T 區（V Cut 區） | T → O/P | 上料區 |

### 上料區與下料區綁定關係
- 一個上料區對應一個下料區，但**多個上料區可綁定同一個下料區**（多對一）
- 綁定關係存放於資料庫 TABLE，可動態調整
- 範例：O1→Q1、P1→Q1、O2→Q2、P2→Q2（實際組數依現場設定）

### 客戶流程圖（已確認）

```
開始
  ↓
初始化搬運系統及物料（OP 將空平板放到所有生產機台的上料儲架）
  ↓
要生產的上料儲架已存在空平板？
  ├─ NO → 等待（OP 手動放置空平板後重試）
  └─ YES → OP 到 SCP 系統驅逐任務
              ↓
         AGV 前往上料儲架，將空平板取起
              ↓
         SCP 判斷目的地，下發給 RCS
              ↓
         下料區是否已有平板？
           ├─ NO → AGV 前往下料區放下空平板
           └─ YES → AGV 依優先級將空平板放到別的地方（M→Q→R）
              ↓
         AGV 前往備料區儲架，將物料取起
              ↓
         AGV 將物料送至上料區
              ↓
         任務結束
```

## 現有相關程式

- **Release 前端邏輯**：`WebGui/SCP/wwwroot/js/Dispatch.js` (Line 1264-1285)

## 討論紀錄

### 已確認事項
1. **觸發方式**：OP 在 SCP 按下派送按鈕時觸發，整合為一個連續流程（空平板回收 + 物料派送）
2. **拆成兩筆獨立任務串接**：任務 1（空平板回收）完成後，才執行任務 2（物料派送）
3. **串接機制**：基於站點狀態判斷（O/P 及 Q 站 HaveFlag），不追蹤任務間關聯，避免 oNeed 清除後失去對照
4. **嚴格卡控（B 方案）**：下料區 Q 必須有空平板（HaveFlag == 1）才允許物料派送至上料區
5. **備料區**：即現有派送區，已有邏輯不需修改
6. **綁定關係**：使用資料庫 TABLE 儲存，svrPair 和 SCP 共用同一份資料
7. **V Cut 區（T區）**：也會派送物料到上料區，需納入同樣的卡控邏輯
8. **可擴展設計**：綁定關係與 FallbackAreas 皆為資料庫設定，未來其他樓層啟用不需改程式

### 各情境處理方式

| O/P 狀態 | Q 狀態 | 處理方式 | 物料是否派送 |
|----------|--------|----------|------------|
| 無空平板 | 有空平板（HaveFlag=1） | 直接派物料 | YES |
| 無空平板 | 無空平板 | 彈窗阻擋：請先人工放置空平板 | NO |
| 有空平板 | 空架（HaveFlag=0） | 空平板送 Q → 再派物料 | YES（等回收完成） |
| 有空平板 | 有空平板（HaveFlag=1） | 空平板送 FallbackAreas → 再派物料 | YES（等回收完成） |
| 有空平板 | 有料盤（HaveFlag=3） | 彈窗阻擋：下料區有料盤，請先處理 | NO |
| 有空平板 | 有空平板 + FallbackAreas 全滿 | 彈窗阻擋：目前沒有可放置的貨架 | NO |

## 選定方案

### 一、資料庫新增 TABLE：oPortBinding

| 欄位 | 型別 | 說明 | 範例 |
|------|------|------|------|
| LoadingPort | nvarchar | 上料區站點 | O1 |
| UnloadingPort | nvarchar | 對應下料區站點 | Q1 |
| FallbackAreas | nvarchar | 空平板回收候補區域（逗號分隔，依序找空位） | M,Q,R |
| UseFlag | nvarchar | 啟用/停用 | Y / N |

### 二、前端卡控（SCP 派送畫面）

**觸發點**：OP 按下派送按鈕時（DispatchController 派送 API）

**檢查邏輯**：
```
當目的地在 oPortBinding 有綁定時：
1. 查 oPortBinding 找到對應下料區 Q
2. 先檢查上料區 O/P 的 HaveFlag：
   - HaveFlag != 1（無空平板）→ 再檢查 Q：
     - Q HaveFlag == 1 → 直接派送（O/P 不需清空平板，Q 已備妥）
     - Q HaveFlag != 1 → 彈窗「上料區及下料區皆無空平板，請先人工放置」
   - HaveFlag == 1（有空平板需搬走）→ 檢查 Q：
     a. Q HaveFlag == 1（已有空平板）→ Q 無法再收，O/P 空平板送 FallbackAreas
        → 依 FallbackAreas 找空位 → 找到則放行 → 全滿則彈窗阻擋
        → 搬完後物料繼續派送（Q 已有空平板，B 條件滿足）
     b. Q HaveFlag == 0（空架）→ O/P 空平板直接送 Q（最理想）→ 放行
     c. Q HaveFlag == 3（有料盤）→ 彈窗「下料區有料盤，請先處理下料區」
```

### 三、後端自動串接（svrPair）

**觸發點**：`GenerateoRequireByoNeed()` 處理到目的地為 O/P 區的 oNeed 時

**邏輯**：
```
每輪循環處理到「目的地為 O/P」的物料 oNeed 時：
1. 查 oPortBinding 找對應下料區 Q
2. 先檢查上料區 O/P 的 HaveFlag：
   - HaveFlag != 1（無空平板）→ 檢查 Q：
     - Q HaveFlag == 1 → 正常轉 oRequire
     - Q HaveFlag != 1 → 跳過，等待下一輪循環
   - HaveFlag == 1（有空平板需搬走）→ 檢查 Q：
     a. Q HaveFlag == 1（已有空平板，B 條件已滿足）
        → 檢查是否已存在空平板回收 oNeed，有則等待
        → 沒有則產生回收 oNeed（O/P → FallbackAreas 找空位）
        → 回收完成後，下一輪循環物料 oNeed 放行
     b. Q HaveFlag == 0（空架）
        → 檢查是否已存在空平板回收 oNeed，有則等待
        → 沒有則產生回收 oNeed（O/P → Q）
        → 回收完成後 Q HaveFlag 變為 1，下一輪循環放行
     c. Q HaveFlag == 3（有料盤）
        → 跳過，等待下一輪循環（前端已卡控此情境）
```

**空平板回收目的地判斷**：
- Q 是空架（HaveFlag == 0）→ 直接送 Q（最理想，Q 補上空平板）
- Q 已有空平板（HaveFlag == 1）→ 依 FallbackAreas 找空位（Q 無法再收）
- Q 有料盤（HaveFlag == 3）→ 不產生回收任務（前端已阻擋）
